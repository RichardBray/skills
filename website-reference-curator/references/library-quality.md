# Evaluate library quality

Assess evidence and retrieval, not the quality of a finished website. Use the [schema and coverage contract](library-model.md#discovery-and-seed-coverage-contract) and catalog validator for structural consistency. Use [source audits](source-audits.md) for observation coverage.

Inspect whether records expose reusable elements with evidence, fit/adaptation notes and honest unknowns. Test representative search queries for different brands and interactions; examine the returned records rather than treating lexical rank as a quality score. Check discovery links, duplicate/stale records, source dates, historical-version caveats and component licence boundaries. Do not broaden reviewed coverage merely to eliminate unknowns.

Report structural failures separately from missing visual/mobile/motion inspection and retrieval weaknesses. Prefer targeted enrichment over adding many unreviewed URLs. Evaluate client build outcomes through the builder's evaluation workflow when the user requests an actual website trial; do not launch builds as part of an ordinary library audit.
