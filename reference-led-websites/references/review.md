# Review the rendered result

- Compare reference and implementation with their different brands and content in mind.
- Record specific observations and fixes rather than an invented quality score.

- Brand fit:
  - the visual direction suits:
    - the audience;
    - positioning;
    - assets;
    - desired action.
  - The site has its own client identity.
- Reference fidelity:
  - compare reference/build at:
    - matching viewport sizes;
    - equivalent start/mid/end scroll states.
  - Check:
    - section order;
    - heights;
    - dominant colour fields;
    - type scale including small utility text;
    - focal-object scale;
    - framing;
    - button shape;
    - hover response;
    - decorative motion;
    - persistent navigation.
  - Each source-to-element mapping must reproduce its intended composition or behaviour.
  - Explain deviations.
  - Fix the largest mismatches first.
  - Do not substitute a generic page because its components function.
- Typography and copy: apply the [detailed checks](#typography-and-copy-checks).
- Layout:
  - clear focal points;
  - reading order;
  - deliberate section rhythm;
  - consistent local alignment;
  - no accidental gaps or overflow.
- Assets:
  - purposeful subject/crop/light;
  - no distorted or unresolved images;
  - rights/source notes for used assets.
- Motion: apply [motion verification](#motion-verification) against the documented contracts and required effects.
- Client functionality:
  - the following required items work:
    - links;
    - menus;
    - forms;
    - error/success states.
  - Do not send a live form submission or message merely to test without authorization.
  - Use a test endpoint or safe local verification.
- Mobile: the following are intentionally adapted:
  - content order;
  - tap targets;
  - navigation;
  - scene fallback;
  - text readability.
- Delivery:
  - the following are recorded:
    - appropriate build checks;
    - actual visual checks;
    - observed loading/runtime issues;
    - remaining limitations.
  - Do not claim production readiness for untested integrations.

- If the output feels generic, identify the cause: weak assets, unrelated typography, default component styles, repetitive section structure, or failure to implement a chosen source element.
- Fix that cause rather than adding arbitrary decoration.

## Motion verification

- Use the canonical [motion contract](animation-patterns.md#motion-contract) to identify expected behaviour.
- Use [motion requirements](motion-requirements.md) to judge whether the required effects are present.
- Record observations against each effect rather than maintaining a second field list.

- For every effect, inspect:
  - start states;
  - intermediate states;
  - settled states;
  - reverse/interruption/revisit;
  - desktop/mobile;
  - reduced-motion alternatives.
  - Use comparable actions for reference/build comparison.
  - Use comparable viewport sizes for reference/build comparison.
  - Check performance.
  - Confirm all content remains accessible.
- For scroll effects:
  - scroll down;
  - back up;
  - then resize.
  - Check for:
    - stuck pins;
    - layout jumps;
    - inaccessible sections.
  - For custom input handling, also run the source audit described in [library access](library-access.md).
- For page transitions, exercise:
  - primary routes;
  - direct URLs;
  - back/forward;
  - rapid/repeated clicks;
  - loading/failure states;
  - unsupported-enhancement fallbacks.
  - Check:
    - shared-element matching;
    - cleanup of prior animation state;
    - focus destination;
    - scroll restoration;
    - that no overlay or navigation lock remains.
- For dialogs, drawers, checkout steps and confirmations, exercise:
  - opening;
  - closing;
  - rapid reversal;
  - Escape/backdrop dismissal;
  - focus containment/restoration;
  - scroll behaviour.
  - Quantity updates should remain stable.
  - Preserve native semantics.
  - Keep routine actions responsive.
- For source audits:
  - Distinguish tested source behaviour from proposed improvements;
  - mark untested cases.
- For builds, before reporting completion:
  - fix failures;
  - rerun affected checks.

## Typography and copy checks

- Use the font-size defaults in [Essential requirements](../SKILL.md#essential-requirements).
- These are project preferences, not a claim of an accessibility standard.
- Adapt layout and wrapping instead of shrinking text.
- A reference's tiny utility type does not override them.
- Check:
  - font loading;
  - hierarchy;
  - measure;
  - wrapping;
  - spacing.

- Do not use em dash characters (U+2014) in any authored website copy, including:
  - metadata;
  - alt text;
  - labels;
  - errors;
  - generated packaging text;
  - image prompts containing visible text.
- Rewrite the sentence with a full stop, comma, colon or parentheses as appropriate.
- Do not mechanically replace them with double hyphens.
- Preserve factual meaning when editing supplied copy.
- Preserve raw reference captures and third-party source evidence unchanged.

- During review, inspect computed font sizes:
  - in rendered desktop states;
  - in rendered mobile states;
  - including open drawers/dialogs;
  - including validation messages.
- Check that the chosen font remains comfortable to read at the minimum size.
- Search authored content and rendered text for:
  - literal em dashes;
  - encoded equivalents such as &mdash;, &#8212;, &#x2014;
  - escaped Unicode.
- Inspect visible text in generated imagery too.
- Fix violations before delivery.
- Report any explicit user-approved exceptions.
